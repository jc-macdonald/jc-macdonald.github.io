Spatial diffusion

OP System compiles a named-axis expression for a periodic diffusion stencil; OP Engine integrates the resulting field with fourth-order Runge–Kutta (RK4). The stencil is supplied explicitly on 64 equally spaced cells. Faster spatial variation fades sooner than slower variation.

The code checks the full trajectory against the exact Fourier-mode solution of the discrete spatial stencil, with a maximum absolute difference below 2e-10. This measures temporal integration error for the chosen grid. It does not measure error against a continuum PDE or establish accuracy for other spatial discretizations.

Stochastic transfers

OP Engine runs 512 independent realizations of a two-state transfer process using the exact stochastic simulation algorithm (SSA), with one event clock per run. Each starts with 40 units; each remaining unit transfers at rate 0.6. The example retains the accepted firing counts and checks conservation and the correspondence between counts and transferred units.

Replicated designs

trade-study evaluates ten sample-mean designs using 512 paired replicates. The measurement standard deviation is either 1 or 1.5. The noisier measurement is assigned a lower cost; the standard measurement has a fixed setup cost. Those costs are illustrative assumptions. The circles mark designs for which no alternative improves both mean error and assumed cost.

The table reads the same generated data as the figure. Error estimates depend on these 512 simulated replicates. A design is nondominated when no other design is at least as good on both stated objectives and better on at least one. Choosing a design for an application also requires preferences or constraints relevant to that application.

Incomplete data

VBPCApy fits a two-component model to observed entries of a noisy synthetic matrix. Roughly 35% of entries are withheld, shown in gray. The generating signal uses two patterns; that choice is supplied to the fitted model.

The root mean squared reconstruction error on withheld noisy observations is about 0.22 for this seeded example; the generating noise standard deviation is 0.2. This is one reconstruction check with a known component count. Choosing the rank and assessing uncertainty calibration require separate studies.

Inference calibration

op_infer evaluates one Normal-model fixture for which the posterior density is available analytically. The left panel compares 1,024 seeded draws from that fixture with the exact posterior density. The right panel summarizes randomized-rank probability-integral-transform values from 64 simulation-based calibration (SBC) replicates.

The fixture completed all 64 requested replicates without a failed attempt. Its recorded gate label is underpowered pass: the implementation and accounting checks passed, but the replicate count is below the prespecified power floor. The histogram is therefore a software demonstration, not a calibration certificate or application result.

OP stack design and verification

These examples show design choices of OP System and OP Engine on synthetic models, each with an independent check. They use released OP System 0.10.0 and OP Engine 0.9.1 with JAX and CPU PyTorch. Every figure reports software behavior within the packages’ documented scope, not a finding about a study system. The research page compares the stack with related tools.

The array library is chosen at call time. OP System compiles a validated, declarative description (equations or hazard-style transitions, with named axes for groups, space and traits) into one evaluator. The array library is selected from the inputs, so the same compiled model runs under NumPy, under JAX and, within the documented qualified scope, under PyTorch. The numerical method does not change with the namespace.

Model authors can check a compiled model. OP System’s qualification report compares a compiled right-hand side with equations the author writes independently, under each array library and precision, and records optional balance checks with their stated conditions.

A model written for one run can be batched or differentiated. The same compiled evaluator can be mapped over a parameter grid or differentiated with respect to a parameter without being rewritten.

One specification, several solvers. OP Engine takes compiled models into explicit and adaptive ordinary-differential-equation methods, operator-split and implicit schemes for partial differential equations, exact stochastic simulation with retained event counts, tau-leaping and steady-state solves. The compiler publishes interface contracts, and the engine owns time integration; the user supplies any spatial discretization.
